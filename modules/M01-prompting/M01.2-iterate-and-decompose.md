## 0. Terms first — Giải thích thuật ngữ trước

- **iteration / vòng lặp cải thiện**: làm một phiên bản, xem kết quả, rồi sửa yêu cầu có mục tiêu.
- **decomposition / chia nhỏ tác vụ**: tách một việc lớn thành các phần nhỏ dễ thực hiện và kiểm tra.
- **follow-up / yêu cầu tiếp nối**: yêu cầu mới dùng context của cuộc chat hiện tại để sửa, mở rộng hoặc tiếp tục task.
- **steering / điều hướng**: hướng ChatGPT sang cách làm mong muốn bằng feedback cụ thể trong lúc làm.
- **checkpoint / điểm kiểm tra**: thời điểm dừng để review trước khi đi tiếp.
- **scope / phạm vi**: phần việc được phép xử lý trong một task.
- **dependency / phần phụ thuộc**: một bước cần kết quả của bước trước mới làm đúng được.

## 1. Learning objectives — Mục tiêu học tập

### English
By the end of this lesson, you can:

- improve a response through targeted follow-ups
- decompose a complex task into reviewable steps
- decide when to continue the same chat and when to start a new one
- use checkpoints instead of changing everything at once

### Tiếng Việt
Sau bài này, bạn có thể:

- cải thiện response bằng follow-up có mục tiêu
- chia task phức tạp thành các bước có thể review
- quyết định khi nào tiếp tục chat hiện tại và khi nào mở chat mới
- dùng checkpoint thay vì sửa mọi thứ cùng lúc

## 2. Key vocabulary — Từ vựng trọng tâm

| Term | Nghĩa tiếng Việt | Plain English | Trong ChatGPT |
|---|---|---|---|
| `iteration` | vòng lặp cải thiện | Repeating a task with targeted changes. | Prompt → response → feedback → revised response. |
| `decomposition` | chia nhỏ tác vụ | Breaking a large task into smaller parts. | Research → compare → decide → draft. |
| `follow-up` | yêu cầu tiếp nối | A later instruction in the same conversation. | Dùng context trước đó thay vì lặp lại toàn bộ. |
| `steering` | điều hướng | Guiding the work while it is in progress. | Nêu phần đúng, phần cần sửa, và mục tiêu của lần sửa. |
| `checkpoint` | điểm kiểm tra | A planned review point. | Dừng sau outline hoặc data extraction trước khi viết final. |
| `scope` | phạm vi | The part of the work included in the task. | Chỉ sửa phần A, không đổi phần B. |
| `dependency` | phụ thuộc | Something that must happen before another step. | Phải có dữ liệu trước khi tính toán. |

## 3. Core concept — Khái niệm cốt lõi

### English
Good prompting is usually iterative. The first prompt does not need to predict every issue. Run a clear version, inspect the result, then make the smallest useful correction. For larger tasks, split work at natural verification points.

### Tiếng Việt
Prompting tốt thường là quá trình lặp. Prompt đầu không cần đoán trước mọi vấn đề. Hãy chạy một phiên bản đủ rõ, xem kết quả, rồi sửa đúng phần gây lỗi. Với task lớn, chia tại các điểm có thể kiểm chứng tự nhiên.

## 4. The iteration loop — Vòng lặp cải thiện

```text
Request → Inspect → Diagnose → Targeted follow-up → Verify
Yêu cầu → Kiểm tra → Chẩn đoán → Follow-up có mục tiêu → Kiểm chứng
```

Không nên phản hồi chỉ bằng:

```text
Try again.
```

Tốt hơn:

```text
Keep the structure and all numbers unchanged. Rewrite only the explanation column for a beginner and define each technical term the first time it appears.
```

Follow-up tốt nói rõ:

- điều gì đang ổn và phải giữ;
- điều gì chưa đạt;
- cần sửa phần nào;
- tiêu chí nào dùng để kiểm lần sửa.

## 5. Decompose at verification boundaries — Chia task tại ranh giới kiểm chứng

Một task nên chia khi:

1. có nhiều loại công việc khác nhau;
2. bước sau phụ thuộc mạnh vào bước trước;
3. một lỗi sớm có thể làm sai toàn bộ phần sau;
4. bạn cần review trước hành động tốn tiền, gửi, publish hoặc thay đổi dữ liệu.

### Example / Ví dụ

Task lớn:

```text
Research four website builders, compare them, recommend one, and draft an implementation plan.
```

Có thể chia thành:

```text
Step 1: Define comparison criteria from my constraints.
Checkpoint: I approve the criteria.

Step 2: Collect current facts for the four options.
Checkpoint: Verify prices and features against sources.

Step 3: Compare and recommend one option.
Checkpoint: Review the trade-offs.

Step 4: Draft the implementation plan for the approved option.
```

**Lợi ích:** nếu criteria sai, bạn sửa ở Step 1 thay vì phải làm lại toàn bộ report.

## 6. Same chat or new chat? — Tiếp tục chat hay mở chat mới?

### Continue the same chat / Tiếp tục chat hiện tại khi

- task vẫn cùng mục tiêu;
- follow-up cần dùng output vừa tạo;
- bạn đang refinement cùng một deliverable;
- context trước đó vẫn đúng và hữu ích.

### Start a new chat / Mở chat mới khi

- mục tiêu đổi sang task không liên quan;
- context cũ dễ gây nhầm;
- bạn muốn một baseline sạch để so sánh hai cách làm;
- cuộc chat đã tích lũy nhiều giả định hoặc hướng dẫn lỗi thời.

**Rule / Quy tắc:** reuse context when it helps; reset context when it contaminates the task.

## 7. Full example — Ví dụ trọn vẹn

### Initial prompt

```text
Create a one-week study plan for learning ChatGPT. I have 6 hours total.
```

### Response problem

Giả sử response chia đều 7 ngày, mỗi ngày 1 giờ — tổng 7 giờ, vượt constraint.

### Diagnose

- Goal đúng: study plan.
- Context thiếu hoặc bị vi phạm: chỉ có 6 giờ tổng.
- Output chưa có cách kiểm tổng thời lượng.

### Targeted follow-up

```text
Keep the same topics, but revise the schedule so the total study time is exactly 6 hours. Show the duration for each session and add a total at the bottom. Do not add new topics.
```

### Verification

Cộng lại tổng thời gian; kiểm danh sách topic không đổi.

**Bài học:** follow-up sửa lỗi cụ thể tốt hơn bắt hệ thống làm lại từ đầu.

## 8. Guided practice — Bài có hướng dẫn

Task:

```text
Create a comparison of three website builders for a beginner freelancer.
```

### Round 1 — First output

Sau response đầu, kiểm ba câu:

- Criteria đã phản ánh budget và custom domain chưa?
- Có fact hiện tại nào chưa có source không?
- Recommendation có nêu trade-off không?

### Round 2 — Targeted correction

Ví dụ:

```text
Keep the three options. Add columns for monthly cost, custom domain, setup difficulty, and maintenance. Mark any unverified current value as Unknown instead of guessing.
```

### Round 3 — Decision refinement

```text
Using only the verified rows in the table, recommend one option for a non-technical freelancer with a $15/month budget. Explain the main downside in two bullets.
```

## 9. Self practice — Bài tự làm

Chọn một task thật hoặc dùng task giả lập này:

> Bạn có 9 giờ/tuần để học, muốn ưu tiên ChatGPT fundamentals trước automation, và cần ít nhất một buổi review cuối tuần.

Yêu cầu:

1. Viết prompt đầu tiên.
2. Chạy và lưu response.
3. Chỉ ra ít nhất một điểm cần cải thiện.
4. Viết follow-up thứ nhất chỉ sửa điểm đó.
5. Viết follow-up thứ hai để tăng khả năng kiểm chứng hoặc usability.
6. Ghi lại thay đổi nào thực sự hữu ích.

Không được dùng `make it better` hoặc `try again` làm follow-up duy nhất.

## 10. Answer guide and rubric — Gợi ý đáp án và rubric

Một chuỗi tốt có thể như sau:

```text
Prompt 1:
Create a weekly ChatGPT study plan using 9 hours total. Prioritize fundamentals before automation and reserve Sunday for review.

Follow-up 1:
Keep the topics and order. Add exact duration to each session and make the weekly total exactly 9 hours.

Follow-up 2:
Add one observable completion criterion to each session so I can mark it PASS or REVIEW. Do not add new study topics.
```

### Rubric 0–2

- `0`: follow-up chung chung hoặc đổi task mà không kiểm lỗi.
- `1`: có sửa cụ thể nhưng chưa giữ đúng scope/constraint hoặc không verify.
- `2`: chẩn đoán rõ, follow-up chỉ sửa phần cần thiết, giữ phần đúng và có verification.

PASS bài tự làm khi cả hai follow-up đều đạt ít nhất `1`, trong đó ít nhất một follow-up đạt `2`.

## 11. English patterns for AI work — Mẫu câu tiếng Anh dùng với AI

| Pattern | Nghĩa / cách dùng |
|---|---|
| `Keep ... unchanged.` | Giữ phần đang đúng. |
| `Revise only ...` | Chỉ sửa một phần. |
| `Before continuing, show me ...` | Tạo checkpoint. |
| `Break this task into ...` | Chia tác vụ. |
| `Do not proceed to the next step until ...` | Dừng trước bước phụ thuộc. |
| `Start a fresh analysis using only ...` | Tạo baseline sạch. |

## 12. Verification — Kiểm chứng

Sau mỗi vòng lặp:

- lỗi mục tiêu có thực sự giảm không?
- constraint cũ có bị phá khi sửa lỗi mới không?
- output có xuất hiện fact mới cần source không?
- task có đang bị scope creep — phạm vi phình ra ngoài mục tiêu — không?
- nếu mở chat mới, bạn đã mang sang đủ context cần thiết chưa?

## 13. Failure modes — Lỗi thường gặp

- Sửa năm thứ cùng lúc nên không biết thay đổi nào có ích.
- Dùng follow-up mơ hồ như `better`, `improve`, `try again`.
- Giữ một chat quá lâu dù mục tiêu đã đổi.
- Mở chat mới nhưng quên mang theo constraints quan trọng.
- Chia task theo số bước tùy ý thay vì theo dependency/verification.
- Cho hệ thống làm tiếp bước tốn tiền hoặc khó hoàn tác mà không checkpoint.

## 14. PASS criteria — Tiêu chí PASS

### ChatGPT track

- [ ] Explain: giải thích iteration, decomposition và checkpoint.
- [ ] Execute: hoàn thành task qua ít nhất 2 follow-up có mục tiêu.
- [ ] Diagnose: chỉ ra cụ thể phần chưa đạt trong response đầu.
- [ ] Verify: chứng minh một thay đổi làm output tốt hơn theo tiêu chí xác định trước.
- [ ] Transfer: quyết định đúng same chat/new chat cho một task khác.

### English track

- [ ] Recognize 6/7 thuật ngữ chính.
- [ ] Understand `steering`, `checkpoint`, `scope`.
- [ ] Use ít nhất hai mẫu follow-up tiếng Anh đúng nghĩa.
