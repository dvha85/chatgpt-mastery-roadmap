## 0. Terms first — Giải thích thuật ngữ trước

- **Chat**: chế độ hội thoại nhanh trong ChatGPT, phù hợp hỏi đáp, viết lại, động não và xử lý việc ngắn.
- **Work**: trải nghiệm ChatGPT dành cho công việc lớn hơn, nhiều bước, nhiều nguồn hoặc cần một sản phẩm hoàn chỉnh để review.
- **Codex**: tác nhân AI chuyên cho phát triển phần mềm, như đọc/sửa code, chạy lệnh, chạy test và làm việc với repository.
- **surface / bề mặt làm việc**: cách hoặc khu vực bạn chọn để tương tác với ChatGPT, ví dụ Chat, Work hoặc Codex.
- **tool / công cụ**: khả năng bổ sung mà hệ thống có thể dùng để lấy dữ liệu hoặc thực hiện một loại việc, ví dụ web search, file analysis hoặc chạy test. Tool không đồng nghĩa với surface.
- **deliverable / sản phẩm bàn giao**: kết quả hoàn chỉnh có thể review hoặc sử dụng.
- **repository / kho mã nguồn**: nơi lưu code, file và lịch sử thay đổi của dự án.

Nếu tài khoản của bạn chưa thấy Work, hãy học cách chọn surface bằng tình huống và dùng Chat làm fallback. Không coi việc chưa thấy một nút trên giao diện là lỗi của người học.

## 1. Learning objectives — Mục tiêu học tập

### English
By the end of this lesson, you can:
- explain the difference between Chat, Work, and Codex in simple language;
- choose a suitable surface for a task and explain why;
- separate the idea of a surface from the idea of a tool.

### Tiếng Việt
Sau bài này, bạn có thể:
- giải thích đơn giản sự khác nhau giữa Chat, Work và Codex;
- chọn surface phù hợp cho một nhiệm vụ và nêu lý do;
- phân biệt surface với tool;
- nhận ra khi nào nên tiếp tục ở Chat và khi nào nên chuyển sang Work hoặc Codex.

## 2. Key vocabulary — Từ vựng trọng tâm

| Term | Nghĩa tiếng Việt | Plain English | Trong ChatGPT |
|---|---|---|---|
| `surface` | bề mặt/cách làm việc | The experience where you do the task. | Chat, Work, Codex. |
| `Chat` | chế độ hội thoại | Fast conversational help. | Hỏi đáp, rewrite, brainstorm, phân tích ngắn. |
| `Work` | chế độ công việc | An experience for larger multi-step work. | Nghiên cứu, phân tích, tạo deliverable nhiều bước. |
| `Codex` | tác nhân lập trình | An AI coding agent. | Đọc/sửa code, chạy test/lệnh, làm việc với repo. |
| `tool` | công cụ | An extra capability used for part of a task. | Search, file analysis, browser, terminal. |
| `deliverable` | sản phẩm bàn giao | A finished usable result. | Report, spreadsheet, document, code change. |
| `repository` | kho mã nguồn | A managed collection of project files/history. | Nơi Codex đọc/sửa code và kiểm tra thay đổi. |

## 3. Core concept — Khái niệm cốt lõi

### English
Choose the surface from the nature of the work, not from which button feels more powerful. Chat is optimized for quick conversational help. Work is better for multi-step work or a completed deliverable. Codex is specialized for software development and repository work.

### Tiếng Việt
Hãy chọn surface dựa trên **bản chất công việc**, không dựa trên cảm giác “nút nào mạnh hơn”. Chat phù hợp trợ giúp nhanh theo hội thoại. Work phù hợp khi việc có nhiều bước, nhiều nguồn/tool hoặc cần deliverable hoàn chỉnh. Codex chuyên cho phát triển phần mềm và repository.

Tool giải quyết một phần việc; surface định hình toàn bộ workflow. Việc dùng web search không tự động biến một câu hỏi ngắn thành task cho Work.

## 4. Mental model — Mô hình tư duy

```text
Việc chính là gì?
      |
      +-- Hỏi nhanh / viết lại / brainstorm / phân tích ngắn?
      |      -> Chat
      |
      +-- Nghiên cứu / phân tích / tạo sản phẩm nhiều bước?
      |      -> Work
      |
      +-- Code / repository / command / test / code review?
             -> Codex

Sau đó mới hỏi: cần tool nào?
```

Ba câu hỏi trước khi bắt đầu:

1. **Có bao nhiêu bước?** Một hoặc vài bước ngắn thường hợp Chat; nhiều bước phụ thuộc nhau nghiêng về Work.
2. **Kết quả cuối là gì?** Nếu cần deliverable hoàn chỉnh để review, Work thường phù hợp hơn.
3. **Lập trình có phải việc chính không?** Nếu repository, code change và test là trung tâm, chọn Codex.

## 5. Examples — Ví dụ

### Example 1 — Chat

**Nhiệm vụ:** Giải thích domain khác hosting thế nào cho freelancer mới.

**Lựa chọn:** Chat.

**Prompt tiếng Việt — dùng trực tiếp**

```text
Hãy giải thích sự khác nhau giữa tên miền (domain) và hosting cho một freelancer mới bắt đầu. Dùng một phép so sánh dễ hiểu và một bảng hai cột. Giới hạn dưới 250 từ. Trả lời bằng tiếng Việt.
```

**English reference — Tham khảo tiếng Anh**

```text
Explain the difference between a domain and hosting for a beginner freelancer. Use one analogy and a two-column table. Keep it under 250 words.
```

**Vì sao:** task ngắn, đầu ra rõ, không cần nhiều bước hoặc repository.

### Example 2 — Work

**Nhiệm vụ:** Từ 5 nguồn và một brief, tạo báo cáo so sánh 5 website stack có bảng, nguồn và khuyến nghị.

**Lựa chọn:** Work.

**Task brief tiếng Việt — dùng trực tiếp**

```text
Kết quả cần đạt: Tạo báo cáo so sánh 5 lựa chọn website stack đủ rõ để ra quyết định.
Ngữ cảnh: Đối tượng là freelancer Việt Nam chưa hiểu domain, hosting hoặc website builder.
Công cụ/nguồn: Dùng brief đính kèm và các nguồn web hiện tại.
Dạng đầu ra: Bảng so sánh + khuyến nghị + trade-off chính.
Kiểm chứng: Trích dẫn các fact hiện tại; tách dữ kiện khỏi khuyến nghị; đánh dấu rõ mọi điểm chưa chắc chắn.
Ngôn ngữ đầu ra: Tiếng Việt.
```

**Vì sao:** nhiều nguồn, nhiều bước và cần deliverable hoàn chỉnh.

### Example 3 — Codex

**Nhiệm vụ:** Sửa lỗi trong repository khiến unit test thất bại, chạy test và tóm tắt diff.

**Lựa chọn:** Codex.

**Prompt tiếng Việt — dùng trực tiếp**

```text
Kiểm tra các test đang thất bại, xác định bản sửa nhỏ nhất và an toàn, thực hiện sửa, chạy các test liên quan rồi tóm tắt các file đã thay đổi và bằng chứng kiểm chứng. Không sửa các file không liên quan. Báo cáo kết quả bằng tiếng Việt; giữ nguyên tên file, lệnh và định danh code.
```

**Vì sao:** code, repository, test và thay đổi file là phần cốt lõi.

### Example 4 — Surface và tool là hai khái niệm khác nhau

**Nhiệm vụ:** Hỏi giá hiện tại của một sản phẩm và cần nguồn.

**Lựa chọn:** Chat + web search tool.

**Prompt tiếng Việt — dùng trực tiếp**

```text
Hãy tìm giá hiện tại của sản phẩm này. Dùng nguồn web mới, ưu tiên trang chính thức, trích dẫn nguồn và ghi ngày kiểm tra. Trả lời bằng tiếng Việt.
```

**Vì sao:** đây vẫn là câu hỏi ngắn nên Chat đủ; web search chỉ là tool cần để lấy dữ liệu mới.

## 6. Vietnamese operational patterns — Mẫu lệnh tiếng Việt dùng trực tiếp

| Mẫu tiếng Việt | Dùng khi |
|---|---|
| `Surface nào phù hợp nhất cho task này, và vì sao?` | Chọn Chat, Work hoặc Codex. |
| `Hãy thực hiện task này đến khi có kết quả hoàn chỉnh để tôi review.` | Giao việc nhiều bước. |
| `Dùng repository và chạy các test liên quan.` | Giao việc lập trình. |
| `Dùng web search cho thông tin hiện tại và trích dẫn nguồn.` | Yêu cầu dữ liệu mới. |
| `Dừng trước mọi hành động khó hoàn tác.` | Đặt ranh giới an toàn. |

### English patterns — Mẫu câu tiếng Anh để học

| English pattern | Nghĩa / cách dùng |
|---|---|
| `Which surface is best for this task, and why?` | Hỏi surface phù hợp. |
| `Carry this task through to a reviewable result.` | Giao việc nhiều bước. |
| `Use the repository and run the relevant tests.` | Công việc code/repo. |
| `Use web search for current facts and cite the sources.` | Fact hiện tại. |
| `Stop before any irreversible action.` | Ranh giới an toàn. |

## 7. Practice — Thực hành

### A. Comprehension check
Với mỗi tình huống, ghi `Chat`, `Work` hoặc `Codex`, sau đó ghi tool nếu cần:
1. Viết lại một đoạn giới thiệu dịch vụ 120 từ.
2. Tạo báo cáo nghiên cứu 10 trang từ nhiều nguồn và file đầu vào.
3. Sửa bug trong repository và chạy test.
4. Hỏi tỷ giá hiện tại và yêu cầu nguồn.

### B. ChatGPT exercise
Chọn một việc thật của bạn và viết:

```text
Surface chính: ...
Lý do: ...
Tool cần: ...
```

Sau đó gửi:

```text
Hãy phản biện lựa chọn surface của tôi dựa trên bản chất task. Nếu bạn chọn khác, giải thích rõ vì sao. Trả lời bằng tiếng Việt.
```

### C. English exercise
Viết ba câu tiếng Anh, mỗi câu dùng một từ: `surface`, `tool`, `deliverable`. Dịch sang tiếng Việt.

### D. Real-world transfer
Lấy một task bạn từng làm bằng nhiều prompt trong Chat. Xác định task đó thực ra nên ở Chat, Work hay Codex và giải thích bằng tiếng Việt.

## 8. Verification — Kiểm chứng

- Lựa chọn surface có dựa trên task hay chỉ dựa trên “cái mạnh nhất”? 
- Tool có phục vụ một nhu cầu cụ thể không?
- Nếu task có fact hiện tại, bạn đã dùng nguồn hiện tại chưa?
- Nếu task code, đã có test hoặc diff review chưa?
- Nếu có hành động khó hoàn tác, đã có điểm human review chưa?

## 9. Failure modes — Lỗi thường gặp

- Coi Work là “Chat mạnh hơn” cho mọi việc.
- Coi Codex là lựa chọn cho mọi task kỹ thuật dù không có code/repo.
- Nhầm surface với tool.
- Dùng web search rồi nghĩ bắt buộc phải chuyển sang Work.
- Không xác định deliverable trước khi giao task lớn.
