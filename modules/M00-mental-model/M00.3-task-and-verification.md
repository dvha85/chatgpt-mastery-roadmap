## 0. Terms first — Giải thích thuật ngữ trước

Bài này dùng một khung giao việc. Các thuật ngữ chính:

- **task / nhiệm vụ**: việc cụ thể bạn muốn ChatGPT giúp hoàn thành.
- **task brief / bản giao việc ngắn**: mô tả đủ rõ về kết quả cần đạt, context, tool cần thiết và cách kiểm chứng.
- **outcome / kết quả cần đạt**: trạng thái cuối hoặc sản phẩm cuối bạn muốn nhận được.
- **context / ngữ cảnh**: thông tin cần thiết để hiểu task và làm đúng phạm vi.
- **tool / công cụ**: khả năng bổ sung cần dùng để lấy dữ liệu, tính toán, thao tác file, chạy code hoặc làm một phần công việc.
- **verification / kiểm chứng**: cách bạn xác nhận output đúng, đủ và có bằng chứng phù hợp.
- **boundary / ranh giới**: điều hệ thống không được làm hoặc phạm vi không được vượt qua.
- **acceptance criteria / tiêu chí chấp nhận**: các điều kiện cụ thể để bạn quyết định output đã “đạt” hay chưa.

Khung chính của M00 là:

```text
Outcome -> Context -> Tools -> Verification
Kết quả -> Ngữ cảnh -> Công cụ -> Kiểm chứng
```

## 1. Learning objectives — Mục tiêu học tập

### English
By the end of this lesson, you can:

- turn a vague request into a clear task brief
- specify outcome, context, tools, boundaries, and verification
- define simple acceptance criteria before running a task
- verify an answer using sources, calculations, tests, or human review

### Tiếng Việt
Sau bài này, bạn có thể:

- biến một yêu cầu mơ hồ thành task brief rõ ràng
- nêu outcome, context, tools, boundaries và verification
- đặt acceptance criteria đơn giản trước khi chạy task
- kiểm chứng câu trả lời bằng nguồn, phép tính, test hoặc review con người

## 2. Key vocabulary — Từ vựng trọng tâm

| Term | Pronunciation | Nghĩa tiếng Việt | Plain English | In ChatGPT / AI |
|---|---|---|---|---|
| `task` | /tɑːsk/ | nhiệm vụ | A piece of work to complete. | Một việc có mục tiêu cụ thể. |
| `brief` | /briːf/ | bản mô tả ngắn | A compact description of what to do. | Ghi outcome, context, constraints, tools và checks. |
| `outcome` | /ˈaʊtkʌm/ | kết quả cần đạt | The result you want at the end. | Report, decision, table, code fix, summary. |
| `boundary` | /ˈbaʊndəri/ | ranh giới | A limit the task must not cross. | Không gửi email, không sửa file ngoài scope, không dùng nguồn không rõ. |
| `acceptance criteria` | /əkˈseptəns kraɪˈtɪəriə/ | tiêu chí chấp nhận | Conditions that define a good enough result. | Có 5 lựa chọn, có nguồn, không quá 1.000 từ, test pass. |
| `verification` | /ˌverɪfɪˈkeɪʃən/ | kiểm chứng | A way to confirm the result is correct enough. | Source check, recalculation, test, cross-check, human review. |
| `evidence` | /ˈevɪdəns/ | bằng chứng | Information that supports a conclusion. | Source, test output, data row, calculation, diff. |

### Vocabulary notes — Giải thích thuật ngữ

#### `task brief`
**Plain English:** A short specification of the work and how success will be judged.  
**Tiếng Việt:** Task brief không cần dài. Nó chỉ cần giúp ChatGPT biết “làm gì, dựa vào đâu, dùng gì, kiểm thế nào”.

#### `acceptance criteria`
**Plain English:** Observable conditions that let you say “this result passes.”  
**Tiếng Việt:** Tiêu chí phải kiểm được. “Hay hơn” là mơ hồ; “dưới 300 từ, có 3 lựa chọn và nêu trade-off” thì kiểm được.

#### `verification`
**Plain English:** Verification checks whether the result deserves trust.  
**Tiếng Việt:** Verification không phải câu “hãy kiểm tra lại” chung chung; cần nêu cách kiểm cụ thể.

## 3. Core concept — Khái niệm cốt lõi

### English
Do not treat ChatGPT as a prompt vending machine. Treat it as a system you assign work to. A good task brief gives the system enough information to act and gives you enough criteria to review the result.

The core sequence is:

1. **Outcome:** What useful result should exist at the end?
2. **Context:** What facts, audience, inputs, constraints, and background matter?
3. **Tools:** What capabilities or sources are required?
4. **Verification:** How will we know the result is correct enough?

### Tiếng Việt
Đừng coi ChatGPT như nơi “mua một prompt”. Hãy coi nó như một hệ thống được giao việc. Task brief tốt giúp hệ thống có đủ thông tin để làm và giúp bạn có đủ tiêu chí để review.

Chuỗi cốt lõi:

1. **Outcome:** Cuối cùng phải có kết quả hữu ích nào?
2. **Context:** Fact, audience, input, giới hạn và background nào ảnh hưởng đến task?
3. **Tools:** Cần nguồn hoặc khả năng nào để làm đúng?
4. **Verification:** Dựa vào đâu để biết kết quả đủ đúng?

## 4. The O-C-T-V framework — Khung O-C-T-V

### O — Outcome / Kết quả cần đạt

Đừng viết chỉ: `Research website builders.`

Tốt hơn:

```text
Create a decision-ready comparison of five website builders for Vietnamese freelancers, with a recommendation and the main trade-offs.
```

Outcome tốt trả lời ba câu:

- Ai sẽ dùng kết quả?
- Kết quả ở dạng gì?
- Kết quả giúp quyết định hoặc hành động nào?

### C — Context / Ngữ cảnh

Context thường gồm:

- audience / đối tượng sử dụng
- known facts / dữ kiện đã biết
- input files or links / file hoặc link đầu vào
- budget, deadline, scope / ngân sách, thời hạn, phạm vi
- boundaries / điều không được làm
- output format / dạng đầu ra cần nhận

Chỉ đưa context liên quan. Nhiều context không liên quan cũng có thể làm task kém rõ.

### T — Tools / Công cụ

Không phải task nào cũng cần tool. Hỏi:

- Cần fact hiện tại? -> web search hoặc nguồn mới.
- Cần tính toán/dữ liệu? -> calculator, data analysis hoặc code phù hợp.
- Cần sửa repository? -> Codex và test/tool lập trình.
- Cần nhiều bước và deliverable? -> Work có thể là surface phù hợp, sau đó dùng tool cần thiết bên trong.

Tool phải phục vụ task; không thêm tool chỉ vì có sẵn.

### V — Verification / Kiểm chứng

Verification nên được viết **trước khi chạy task**. Ví dụ:

```text
Verification:
- cite official sources for current prices
- show the calculation for monthly cost
- separate facts from recommendations
- flag missing information instead of guessing
```

Nếu verification chỉ được nghĩ tới sau khi đã thích một câu trả lời, bạn dễ xác nhận thiên lệch.

## 5. Add boundaries and acceptance criteria — Thêm ranh giới và tiêu chí chấp nhận

O-C-T-V là khung tối thiểu. Với task quan trọng, thêm hai phần:

### Boundaries / Ranh giới

```text
Do not send, publish, purchase, delete, or modify external data without my review.
```

**Nghĩa:** Không gửi, đăng, mua, xóa hoặc sửa dữ liệu bên ngoài nếu chưa có review của tôi.

### Acceptance criteria / Tiêu chí chấp nhận

```text
PASS if:
- exactly five options are compared
- every current price has a source
- unknowns are labeled
- the final recommendation explains at least two trade-offs
```

Đây là cách biến “làm tốt” thành điều có thể kiểm.

## 6. Task brief template — Mẫu giao việc

### Short version / Bản ngắn

```text
Outcome / Kết quả:
Context / Ngữ cảnh:
Tools / Công cụ:
Verification / Kiểm chứng:
```

### Practical version / Bản thực dụng

```text
Outcome / Kết quả:
Audience / Đối tượng:
Context and inputs / Ngữ cảnh và đầu vào:
Boundaries / Ranh giới:
Tools or sources / Công cụ hoặc nguồn:
Output format / Dạng đầu ra:
Acceptance criteria / Tiêu chí chấp nhận:
Verification / Cách kiểm chứng:
```

Không cần điền mọi dòng cho task nhỏ. Mục tiêu là giảm mơ hồ, không phải tạo thủ tục hành chính.

## 7. Examples — Ví dụ

### Example 1 — Rewrite task

**Vague / Mơ hồ**

```text
Make this better.
```

**Task brief / Bản giao việc**

```text
Outcome: Rewrite the paragraph so a beginner can understand it in under 120 words.
Context: Keep the original meaning and all numeric values.
Tools: No external tools needed; use only the text I provide.
Verification: Check that no fact or number was added or removed.
```

**Giải thích:** Outcome và verification đủ rõ; không cần Work hay web.

### Example 2 — Current research task

```text
Outcome: Compare three current MacBook-compatible power banks for air travel and recommend one.
Context: The device is a MacBook Air. Priorities are airline-safe capacity, USB-C power delivery, weight, and price.
Tools: Use current web sources; prefer manufacturer and airline/aviation authority sources for technical or travel claims.
Boundaries: Do not treat marketplace listings as the only source for safety limits.
Verification: Cite capacity, output, weight, and travel-rule claims. Mark any conflict between sources.
```

**Giải thích:** Task có fact thay đổi theo thời gian, nên tool và source policy là phần bắt buộc.

### Example 3 — Repository task

```text
Outcome: Fix the failing parser tests with the smallest safe code change.
Context: Do not change public behavior outside the failing cases.
Tools: Inspect the repository, run the focused tests first, then the relevant test suite.
Boundaries: Do not change unrelated files or dependencies unless necessary and explained.
Acceptance criteria: The failing tests pass and no new relevant failures appear.
Verification: Show the test commands, results, and changed-file summary.
```

**Giải thích:** Đây là task cho Codex vì repository, code change và test là trọng tâm.

### Example 4 — Multi-step deliverable

```text
Outcome: Produce a one-page decision memo choosing one website stack for a freelancer portfolio site.
Context: Budget under $15/month; audience is non-technical; must support custom domain and contact form.
Tools: Use the provided brief plus current official product pages.
Boundaries: Stop before purchasing or creating accounts.
Acceptance criteria: Compare at least four viable options, show recurring cost, and explain the top recommendation's main downside.
Verification: Link each current pricing/feature claim to a source and label assumptions.
```

**Giải thích:** Đây là ứng viên tốt cho Work vì có nhiều bước, nhiều nguồn và cần deliverable hoàn chỉnh.

## 8. Verification ladder — Thang kiểm chứng

Không phải claim nào cũng cần cùng mức kiểm. Dùng mức phù hợp với rủi ro:

| Level | Cách kiểm | Dùng khi |
|---|---|---|
| 1 | Format/instruction check — kiểm format và yêu cầu | Rewrite, summary, brainstorming |
| 2 | Source check — mở nguồn và đối chiếu claim | Fact, giá, ngày, luật, feature, quote |
| 3 | Recalculation/test — tính lại hoặc chạy test | Số liệu, code, logic có thể tái hiện |
| 4 | Cross-check — đối chiếu nguồn độc lập hoặc dữ liệu gốc | Claim quan trọng hoặc nguồn xung đột |
| 5 | Human approval — người chịu trách nhiệm duyệt | Gửi/publish/mua/xóa, pháp lý, tài chính, quyền truy cập |

**Rule / Quy tắc:** rủi ro càng cao, verification càng mạnh.

## 9. English patterns for AI work — Mẫu câu tiếng Anh dùng với AI

| English pattern | Nghĩa / cách dùng |
|---|---|
| `The outcome I need is ...` | Nêu kết quả cuối. |
| `Use only the following context ...` | Giới hạn context được phép dùng. |
| `Use current official sources for claims that may have changed.` | Yêu cầu nguồn hiện tại cho claim có thể đổi. |
| `Do not guess when evidence is missing.` | Không đoán khi thiếu evidence. |
| `PASS only if all acceptance criteria are met.` | Chỉ coi là đạt khi đủ tiêu chí. |
| `Stop before sending, publishing, purchasing, or deleting anything.` | Dừng trước hành động khó hoàn tác. |

## 10. Practice — Thực hành

### A. Comprehension check — Kiểm tra hiểu bài

Với yêu cầu `Find the best website tool for me`, hãy chỉ ra ít nhất bốn thông tin còn thiếu thuộc O-C-T-V.

### B. ChatGPT exercise — Bài tập ChatGPT

Chọn một task thật, viết task brief theo bản thực dụng rồi gửi vào ChatGPT. Sau khi có response, không sửa prompt ngay. Trước tiên hãy chấm từng acceptance criterion `PASS/FAIL/UNKNOWN`.

### C. English exercise — Bài luyện tiếng Anh

Viết bốn câu:

1. `The outcome I need is ...`
2. `The relevant context is ...`
3. `Use ... to ...`
4. `Verify ... by ...`

Dịch sang tiếng Việt và kiểm tra câu tiếng Anh có giữ đúng ý định không.

### D. Real-world transfer — Áp dụng thực tế

Lấy một yêu cầu cũ từng khiến bạn phải sửa response nhiều lần. Viết lại thành task brief O-C-T-V. Ghi dự đoán: lần này lỗi nào sẽ được giảm?

## 11. Failure modes — Lỗi thường gặp

- Outcome là một chủ đề chứ không phải kết quả: `Tell me about marketing`.
- Context quá ít khiến model phải đoán.
- Context quá nhiều nhưng không liên quan, làm mục tiêu bị loãng.
- Ghi `use tools` mà không nói tool dùng để làm gì.
- Verification mơ hồ: `double-check everything`.
- Không đặt boundary cho hành động gửi, publish, mua, xóa hoặc sửa dữ liệu.
- Viết acceptance criteria sau khi đã thấy kết quả, khiến tiêu chí bị uốn theo output.

## 12. PASS criteria — Tiêu chí PASS

### ChatGPT track

- [ ] Explain: giải thích đúng O-C-T-V bằng tiếng Việt.
- [ ] Execute: viết một task brief có Outcome, Context, Tools, Verification.
- [ ] Diagnose: chỉ ra ít nhất hai điểm mơ hồ trong một request yếu.
- [ ] Verify: chấm một output theo acceptance criteria và kiểm ít nhất một claim quan trọng.
- [ ] Transfer: áp dụng task brief cho một task thật khác ví dụ trong bài.

### English track

- [ ] Recognize ít nhất 6/7 thuật ngữ trọng tâm.
- [ ] Understand `boundary`, `acceptance criteria`, `verification` trong ngữ cảnh task.
- [ ] Use đủ bốn câu O-C-T-V bằng tiếng Anh.
